# Устройство приложения

Приложение остаётся на Flask, SQLAlchemy и PostgreSQL. HTTP-маршруты и форматы API сохранены; таблицы и защитные триггеры истории этим рефакторингом не менялись.

| Модуль | Назначение |
| --- | --- |
| `glorax/__init__.py`, `config.py`, `extensions.py` | Создание приложения, окружение, TLS, пул БД, заголовки, жизненный цикл сессии |
| `models.py` | Схема ORM, постоянные ID и UTC |
| `settings.py` | Настройки с кешем в пределах транзакции; кеш очищается при commit/rollback |
| `data_access.py` | Пакетная загрузка сущностей и экранирование поиска LIKE |
| `sources/http.py` | Ограниченный HTTP-клиент, robots.txt, повторы, закрытие соединений |
| `sources/decoding.py` | Извлечение встроенных данных и текста PDF |
| `sources/normalization.py` | Преобразование материалов в факты, отдельные денежные выборки |
| `parser.py` | Обход каталога, сбор проектов, отчёт покрытия; прежние импорты парсера и CLI сохранены |
| `facts.py` | Версии фактов, атомарная публикация, ручные правки, экспорт |
| `question_values.py` | Чистые функции сравнения значений и форматирования, шаблоны вопросов |
| `questions.py` | Проверка источников, однозначности, актуальности и генерация версий |
| `selection.py`, `catalogue.py` | Выбор до 20 вопросов по категориям и быстрые счётчики каталога |
| `attempts.py` | Сессионная принадлежность, снимки попыток, серверные дедлайны и оценивание |
| `admin/` | Общая защищённая Blueprint, отдельно отчёты, проекты, вопросы, импорт и операции |
| `jobs.py`, `worker.py` | Постоянная очередь, аренда задания, восстановление, обслуживание таймаутов |
| `importing.py`, `legacy.py` | Проверяемый импорт вопросов и повторяемый перенос SQLite с резервной копией |

## Правила для дальнейших изменений

- SQLAlchemy хранит слабые ссылки на загруженные ORM-объекты. Пакетные загрузчики возвращают контейнеры, которые нужно удерживать до окончания проверки. Не заменяйте их на вызов загрузки с немедленным отбрасыванием результата: это снова создаст сотни SQL-запросов.
- Кеши настроек и принадлежности снимку принадлежат SQLAlchemy-сессии и очищаются на границе транзакции. Общего кеша ORM-объектов между запросами нет. Отсутствующая настройка отличается от явно сохранённого `null`.
- Публикация и ручные правки используют прежнюю advisory-блокировку и транзакцию. Функции работы с фактами не фиксируют частичные снимки. Ошибка сбора сохраняет рабочую версию.
- Таймер и баллы меняются под блокировкой строки попытки. Фоновая проверка выбирает только попытки с истёкшим дедлайном или сроком бездействия, пакетами до 200, с `SKIP LOCKED`. Следующий проход обрабатывает оставшиеся просроченные попытки.
- Итоги CSV и аналитики агрегируются SQL-запросами по неизменяемым снимкам ответов. Текущий банк не используется для переоценки истории.
- Проверки JSON Schema и смысловые проверки фактов выполняются и после пакетной загрузки. Импортированные формулировки остаются черновиками; наличие ID не заменяет проверку смысла.

## Проверки рефакторинга

`tests/test_refactor_regressions.py` проверяет откат настроек, отсутствие N+1 в экспорте/генерации/предпросмотре 100 вопросов, один запрос к ответам на шаг теста, обслуживание только просроченных попыток и безопасную обработку некорректного JSON. `tests/fixtures/routes.json` фиксирует контракт 36 маршрутов.

```sh
python -m ruff check glorax scripts app.py tests
python -m ruff format --check glorax scripts app.py tests
TEST_DATABASE_URL='postgresql+psycopg://user:password@localhost/glorax_test' python -m pytest -q
```

Тестовая PostgreSQL должна быть отдельной от production. Каждый тест использует собственную схему и настоящие миграции. Проверки таймера, конкурентных ответов, прав доступа и неизменяемой истории остаются обязательными. Опциональная браузерная проверка запускается отдельно, как описано в README.
