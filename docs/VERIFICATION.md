# Реально выполненные проверки

Дата: 27.09.2026. Среда: macOS ARM64, Python 3.14.7, PostgreSQL 16.15, Chromium 153. Базы `glorax_test` и `glorax_local` — локальные. Первоначальная реализация проверялась локально. Для исправления Render Free дополнительно проверен уже развёрнутый пользователем сайт через его админку (см. ниже).

## Автоматические тесты

Финальная команда:

```bash
TEST_DATABASE_URL=postgresql+psycopg://glorax_test@127.0.0.1:55432/glorax_test RUN_BROWSER_TESTS=1 .venv/bin/python -m pytest -q
```

Результат: **50 passed in 15.84s**. Включён настоящий Chromium, а не только Flask test client. Каждый тест с БД создаёт отдельную PostgreSQL-схему и накатывает Alembic; SQLite не подменяет транзакционные проверки.

Проверены:

- Извлечение полного embedded-каталога из сохранённого HTML; все регионы, карточки после «Показать ещё», анонсы и сданные дома; отдельный тест явной пагинации, неполноты и изменения структуры.
- Совпадение идентичности проекта, исключение чужого меню, UTF-8 Flight records без исполнения JavaScript, лендинги с ошибочным общим H1, robots, запрет межхостовых и запрещённых перенаправлений.
- Decimal-диапазоны, полная/неполная выборка, исключение кладовых/других валют/акций/цен за метр, неизвестный максимум.
- Уникальность и эквивалентность вариантов (денежные форматы, Unicode, диапазоны, синонимы статусов), происхождение каждого варианта, исключение неоднозначных и просроченных фактов, пустые значения не обрушивают публикацию.
- Повторная генерация без новых дубликатов; смена версии шаблона создаёт версии существующих вопросов и сохраняет прежние.
- Один текущий вопрос без ответного ключа/будущих вопросов/ссылок на факты; неизменные порядок и дедлайн при перезагрузке; серверный отказ после срока; отдельное время следующего вопроса; прерывание по бездействию.
- Шесть конкурентных POST с одним ответом дают ровно один балл; повторные POST идемпотентны; чужая сессия, неизвестный вариант и ещё не открытый вопрос отклоняются.
- Изменение/архивирование банка и проекта не меняет назначенную попытку; PostgreSQL отвергает изменение снимка, дедлайна и удаление строки истории.
- Разделение тёзок без кода и повторная привязка по коду, лимиты по темам без повторов, повторная проверка объявленного размера теста.
- Очередь без параллельного дубликата, восстановление lease, защита от публикации старым worker, сохранение последнего снимка при сбое, транзакционный rollback при ошибке нормализации, сохранение ручной версии и конфликтов.
- Резервная копия и повторный импорт старой SQLite, сохранение исходных ответов без выдуманных формулировок и порядка.
- Закрытые админка/экспорт, CSRF, ограничение входов, HTML-экранирование; рендер всех основных административных страниц.
- JSON Schema, неизвестные project/fact/dataset ID, неверный правильный ключ, повторяющиеся варианты/поля, oversized/NaN JSON, черновики, идемпотентность `external_id`, явное обновление конфликта, атомарность выбранного пакета и импорт валидного подмножества.
- PostgreSQL downgrade до base и upgrade до head; реальные внешние ключи циклических указателей текущих версий.
- Обязательные production-секреты, PostgreSQL, наличие CA и запрет ослабленного sslmode.

## Исправление Render Free (27.09.2026)

На работающем `gloraxtest.onrender.com` проверены `/healthz` (200), вход администратора, каталог и очередь. Каталог пуст, сохранённое задание находилось в `queued` после `OperationalError` на этапе публикации. Таблицы и вход уже работали: это не отсутствие миграций. Старый отчёт не содержал SQLSTATE, поэтому точная причина прежнего сбоя PostgreSQL по нему не установлена. Предоставленная Start Command запускала только миграции и Gunicorn, без постоянного worker.

Добавлены и проверены миграции перед web/worker, начальная постановка без дублей/сброса неудачного задания, остановка обоих сервисов при отказе одного, SIGTERM, диагностика heartbeat и безопасная выдача SQLSTATE без SQL/паролей. Все 50 тестов прошли на PostgreSQL, включая Chromium.

Два реальных запуска `scripts/start_render.py` на отдельных пустых временных PostgreSQL-БД автоматически прошли миграции → очередь → HTTP-сбор → публикацию. Последний: 29 проектов, 58 источников, 1760 версий фактов, 201 опубликованный вопрос; 40,7 секунды до завершения, главная HTTP 200. Во время сбора health check продолжал отвечать. В предыдущем прогоне было 202 вопроса; число не фиксируется в коде и зависит от пригодных фактов/вариантов.

При проверке памяти первоначальный вариант с несколькими worker-процессами потреблял суммарно до 618 МиБ RSS. После компактного worker и потокового разбора Flight — 353 МиБ RSS по сумме дочерних процессов на macOS. Это локальное измерение, не гарантия памяти/нагрузки на Render. Результаты разбора сохранённых каталога и страницы проекта до/после оптимизации полностью совпали. После SIGTERM все дочерние процессы остановились; временные тестовые БД удалены, пользовательская БД не очищалась.

Настройки существующего сервиса Render не изменены: управление браузером недоступно без выданных системных разрешений. Нужно установить Start Command из README; изменение YAML обычного существующего сервиса не заменяет эту настройку. Точное выполнение нового launcher в Render/Aiven требует проверки после deploy.

## Что не проверено и не заявляется готовым

- Новый launcher проверен локально на PostgreSQL; его запуск в Render/Aiven ещё требует изменения Start Command. Админка существующего сайта доступна и прочитана. Проверены настройки `verify-full` и их fail-closed поведение; прямое подключение к конкретной Aiven из локального окружения не выполнялось.
- Не выполнено нагрузочное испытание целевой инфраструктуры; есть проверки гонок PostgreSQL, но они не задают гарантированную пропускную способность.
- Нет полного разрешённого обхода квартирных предложений и утверждённых акционных условий. Максимумы цен отсутствуют, ценовые вопросы автоматически не опубликованы.
- Нет автоматического OCR/PDF-разбора и автоматической смысловой проверки рекламных описаний. Эти сведения и экспертные оценки требуют редакторской проверки; для некоторых категорий недостаточно однозначных вариантов.
- У старой схемы потеряны размер/порядок теста и исторические формулировки. Они не восстановлены искусственно, процент для legacy не рассчитывается.
